# TAB5 ERP 1.0.0 — entrega estável consolidada

09/10/2026. Consolidação autorizada pelo usuário. Branch release/v1.0.0-stable;
tag de distribuição v1.0.0 com os testes finais aprovados. A implementação comercial e de
segurança é a da 0.12; esta entrega alinha versões, instalação, documentação e
pacotes. Não altera schema 008_offline, dados, senhas, PIN ou formatos do microSD.

## Entrega

- TAB5_ERP-v1.0.0-app-OTA.bin: aplicação ESP32-P4 para o launcher já usado no Tab5.
- TAB5_ERP-v1.0.0-server-update.zip: atualização incremental da instalação existente.
- TAB5_ERP-v1.0.0-LICENSES.txt: licença do projeto e da biblioteca Mbed TLS.
- Arquivos .sha256 para conferência dos artefatos.
- Código completo pela branch/tag no GitHub; ZIP incremental não instala base vazia.

Servidor OCI Ampere ARM64, Traefik existente: rede meshcentral_proxy, entrypoint
websecure, resolver letsencrypt, domínio tab5api.ampere.diadiatech.com.br.

## Atualização da instalação existente

Copie o ZIP para /home/ubuntu/TAB5_ERP e execute:

```sh
cd /home/ubuntu/TAB5_ERP
unzip -o TAB5_ERP-v1.0.0-server-update.zip
bash docker/scripts/update-stable.sh
```

O script faz backup antes do build, para a API anterior, aplica migrações pendentes,
recria a API e valida schema, versão 1.0.0, isolamento, auditoria, certificado HTTPS
e cabeçalhos. Preserva .env/secrets/volumes/usuários/dados. Não depende de Git no
servidor. Não executar initialize, reimportar SQL ou apagar volumes.

Depois instale o BIN **da aplicação** pelo M5Launcher habitual, mantendo microSD
com a pasta ERP. Não apagar partições ou regravar por USB nessa atualização.
PIN de quatro números, senha ERP atual, Wi-Fi/API e rascunhos/pendências permanecem.
Firmware e API têm a mesma versão 1.0.0; sem nova exigência de senha ou de conexão.

Confira desbloqueio/login, produto, operação de caixa/venda e recuperação de rascunho
após reinício. Em resultado desconhecido, Resolver usa a chave persistida; não crie
uma nova venda substituta. Para servidor novo, siga installation.md com código
completo; nunca use pacote incremental como se fosse instalador de base vazia.

## Funcionalidades incluídas

Interface pt-BR em paisagem, teclado/touch, PIN local, Wi-Fi/API configuráveis,
login/RBAC, produtos/categorias/preços, clientes e fornecedores, PDV transacional,
pagamentos declarados e cancelamento integral, estoque/movimentos, caixa,
contas/baixas, relatórios SQL, cache incremental e rascunhos criptografados no SD.
Backup/restore, Alembic, auditoria, idempotência, conflitos e recuperação persistente.

Configuração sem NVS por escolha do usuário. Chaves/PIN não gravados no cartão;
tokens/senha ERP não persistidos. TLS verifica CA/hostname/hora; Mbed TLS 3.6.7 do
fork Espressif, SHA-256 fixado, em build isolado. SQL/decimais/transações no servidor;
API sem root/portas/capabilities, imagem e dependências fixadas com hashes.

## Validação e evidências

As etapas até 0.11 receberam confirmações do usuário, incluindo persistência e
HTTPS no OCI, produtos, contatos, vendas, estoque, caixa, relatórios e rascunho
reiniciado/offline. A 0.12 teve 68 testes API, MariaDB AMD64/ARM64, concorrência,
backup/restore, firmware, corrupção/alocação e TLS aprovados (links na release 0.12).
O pedido de geração da 1.0 autoriza a consolidação; não é descrito como resultado
individual de ensaios físicos 0.12 não relatados.

68 testes API aprovados localmente na versão 1.0. Núcleo portátil, armazenamento
AES-GCM, corrupção, falta de memória e TLS real aprovados. Fontes/versões/sintaxe
e segredos conferidos; auditoria das 23 dependências sem avisos ativos no PyPI em
09/10/2026. Build ESP32-P4 1.0 aprovado localmente: 1.729.056 bytes,
com 73% livres no slot OTA de 6 MiB. No commit 9bff721, o CI aprovou
[MariaDB/API AMD64 e ARM64](https://github.com/tpklge/PDVeVENDAS/actions/runs/37894789209)
e [firmware ESP32-P4 e núcleo portátil](https://github.com/tpklge/PDVeVENDAS/actions/runs/37894789213).
A revisão final acrescenta apenas registros de entrega. Firmware não foi gravado
automaticamente, e o servidor OCI não foi alterado nesta sessão.

## Limitações mantidas

PDV/comprovante não fiscal. Pagamentos são declarados pelo operador, sem confirmar
adquirente/Pix, armazenar cartão ou emitir nota fiscal. Cancelamento integral não
comprova reembolso externo; devolução parcial não implementada. Rascunhos offline
não reservam estoque; venda definitiva requer API e caixa aberto. Fila persistente
serial por módulo, com retentativas/resolução explícitas. Sem cartão não existe
configuração ERP para login nem fila financeira segura.

FATFS não promete atomicidade absoluta de queda física de energia. PIN curto tem
menor resistência a adivinhação offline; proteger cartão/backups. Falha física do
cartão, navegação por oito horas, tempos/heap no dispositivo e equivalência bit a
bit entre hosts não foram medidos nesta sessão. Esses limites não são apresentados
como testes aprovados. Não grava eFuses nem exige configuração irreversível.

Ver installation.md, recovery.md, security.md, synchronization.md, performance.md
e final-validation.md para instalação, preservação e operação.
